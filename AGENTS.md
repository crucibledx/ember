## Layout

Packages follow spec 0001 §1 (its acceptance contract names them, so the paths are fixed) and the "Go repos" section
of the engineering standards. One package per bounded context. Domain packages are pure: no I/O, no cobra, no
collector component APIs. Adapters at the edges (commands, collector components, harness adapters, processes) stay
thin and call into them. No `util`, `common` or `helpers` packages.

| Package | Holds | Kind | Arrives with |
|---|---|---|---|
| `cmd/ember` | `main.go` (flags and wiring only); `components.go`, generated by ocb | edge | #6 |
| `internal/buildinfo` | build identity: version, commit, date, linked collector | domain | #18 |
| `internal/cli` | cobra commands only: `version`, `run`, later `setup`, `doctor`, `up`, `down` | edge | #6, #10 |
| `internal/harness` | adapter contract, registry, harness-neutral `Run`, `Change`, `Mapping` | domain | #7 |
| `internal/harness/<name>.go` | one adapter per file; I/O only through `Env` and `fs.FS`; fixtures in `testdata/<name>/` | edge | #8, M2 |
| `internal/tree` | deterministic ids, forest, segments, work id, attribution | domain | #9 |
| `internal/emit` | tree to OTLP spans, logs and metrics | domain | #9 |
| `internal/privacy` | allowlist, deny list, keyed hashing of human ids | domain | #9 |
| `internal/receiver/sessions` | `ember_sessions` receiver: poll loop, `state/sessions.json` | edge | #9 |
| `internal/extension/registry` | `ember` extension: session registry, `/status` | edge | #9 |
| `internal/processor/ember` | `ember` processor, one file per step (re-parent, enrich, tool names) | edge | #9 |
| `internal/config` | Ember config types, decode, one validate function, collector config render | domain | #10 |
| `internal/setup` | plan and apply `Change`s, backups, manifest, undo | application | #10 |
| `internal/doctor` | doctor checks as data: status, message, fix | application | #10 |
| `internal/daemon` | `up` and `down`: pid file, log file, waiting for `/status` | edge | #10 |
| `internal/dashboards`, `dashboards/` | build-time dashboard generator and its generated JSON | build tool | #11 |
| `internal/problems` | workstream problem reports to log records | domain | #16 |
| `internal/stack` | local Docker-free backend for `ember up` | edge | M3 |

Never edit `cmd/ember/components.go` by hand; it comes from [`builder-config.yaml`](builder-config.yaml).

## Tasks

`make` is the task runner (GNU make 3.81 or later and a POSIX shell; on Windows, Git Bash). CI runs the same targets.

| Target | Runs |
|---|---|
| `make check` (default) | `make build vet test lint` |
| `make build` | `go build -o bin/ ./...` (every package; the binary lands in `bin/`) |
| `make vet` | `go vet ./...` |
| `make test` | `go test -race ./...` with cgo on |
| `make lint` | `golangci-lint run` |
| `make generate` | ocb from `builder-config.yaml`, then `components.go`, `go.mod` and `go.sum` |
| `make dist [VERSION=x.y.z]` | five stripped release binaries in `dist/`, then the size gate |
| `make clean` | removes `bin/`, `dist/` and `build/` |

Two checks stay shell scripts in `scripts/`, called by `make dist` and tested on their own in CI:
`check-binary-size.sh` (the size gate; CI feeds it files just over and at the limit) and `check-version.sh` (the
release version is SemVer; cases in `check-version_test.sh`; GoReleaser replaces it in M3).

## How to work

- Nothing is approved product direction until a spec merges, here in `specs/` or in `crucibledx/hq` `specs/`.
  Research notes, roadmaps and unmerged drafts (including the Forge manifest Ember plans to read) are input, not
  decisions.
- Run `make check` before every push (details in the loop contract): `golangci-lint run`, `go vet ./...`,
  `go test -race ./...`, `go build ./...`. The org Bun CI does not apply here.
- A collector component is added or bumped in `builder-config.yaml`, then `make generate`; never with
  `go get` alone. All component versions come from one upstream release.

## Boundaries

- Never push to `main`, force push or merge. Nazar's code-owner approval is the merge gate.
- No tags or publishing in agent PRs; releases are manual. Agents never dispatch the `Go` workflow's manual release
  build.
