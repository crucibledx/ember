## Layout

- `cmd/ember/`: `main.go` (flags and wiring only) and `components.go`, generated by ocb from
  [`builder-config.yaml`](builder-config.yaml). Never edit `components.go` by hand.
- `internal/<package>/`: everything else, per spec §1 and the "Go repos" section of the engineering standards.
- `scripts/`: `generate.sh` (regenerate components and collector requirements), `build.sh` (five stripped release
  targets with the size gate), `check-binary-size.sh`, `check-version.sh` (release version is SemVer; cases in
  `check-version_test.sh`).

## How to work

- Nothing is approved product direction until a spec merges, here in `specs/` or in `crucibledx/hq` `specs/`.
  Research notes, roadmaps and unmerged drafts (including the Forge manifest Ember plans to read) are input, not
  decisions.
- Run the Go checks before every push (details in the loop contract): `golangci-lint run`, `go vet ./...`,
  `go test -race ./...`, `go build ./...`. The org Bun CI does not apply here.
- A collector component is added or bumped in `builder-config.yaml`, then `scripts/generate.sh`; never with
  `go get` alone. All component versions come from one upstream release.

## Boundaries

- Never push to `main`, force push or merge. Nazar's code-owner approval is the merge gate.
- No tags or publishing in agent PRs; releases are manual. Agents never dispatch the `Go` workflow's manual release
  build.
