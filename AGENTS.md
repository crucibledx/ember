## Layout

Packages follow spec 0001 §1 (its acceptance contract names them, so the paths are fixed) and the "Go repos" section
of the engineering standards. One package per bounded context. **Context** packages do no I/O (no `os`, `os/exec`,
`net`, `net/http`, cobra or collector component APIs; `pdata` is fine) and take their own interfaces instead.
**Adapters** at the edges (commands, collector components, processes) stay thin: decode and validate, call a context,
encode the result. Imports point inward: `cmd` → adapters → contexts, never back. Every package under `internal/`
not marked context below is an adapter or tooling. No `util`, `common`, `helpers`, `shared`, `models` or `types`.

| Package | Holds | Kind | Arrives with |
|---|---|---|---|
| `cmd/ember` | `main.go` (flags and wiring only); `components.go`, generated by ocb | `main` | #6 |
| `internal/buildinfo` | build identity: version, commit, date, linked collector | context | #18 |
| `internal/cli` | cobra commands only: `version`, `run`, later `setup`, `doctor`, `up`, `down` | adapter | #6, #10 |
| `internal/harness` | adapter contract, registry, harness-neutral `Run`, `Change`, `Mapping` | context | #7 |
| `internal/harness/<name>.go` | one harness per file in package `harness` (spec §4), so I/O only through `Env` and `fs.FS`; fixtures in `testdata/<name>/` | context | #8, M2 |
| `internal/tree` | deterministic ids, forest, segments, work id, attribution | context | #9 |
| `internal/emit` | tree to OTLP spans, logs and metrics (`pdata`) | context | #9 |
| `internal/privacy` | allowlist, deny list, keyed hashing of human ids | context | #9 |
| `internal/receiver/sessions` | `ember_sessions` receiver: poll loop, `state/sessions.json` | adapter | #9 |
| `internal/extension/registry` | `ember` extension: session registry, `/status` | adapter | #9 |
| `internal/processor/ember` | `ember` processor, one file per step (re-parent, enrich, tool names) | adapter | #9 |
| `internal/config` | Ember config types, decode from an `io.Reader`, one validate function, collector config render | context | #10 |
| `internal/setup` | plan `Change`s, backup manifest, undo rules; file writes through its own interface | context | #10 |
| `internal/doctor` | doctor checks as data (status, message, fix); probes through its own interfaces | context | #10 |
| `internal/daemon` | `up` and `down`: pid file, log file, waiting for `/status` | adapter | #10 |
| `internal/dashboards`, `dashboards/` | build-time dashboard generator and its generated JSON | tooling | #11 |
| `internal/problems` | workstream problem reports to log records | context | #16 |
| `internal/stack` | local Docker-free backend for `ember up` | adapter | M3 |

Never edit `cmd/ember/components.go` by hand; it comes from [`builder-config.yaml`](builder-config.yaml).

## Tasks

`make` is the task runner (GNU make 3.81 or later and a POSIX shell; on Windows, Git Bash). CI runs the same targets.

| Target | Runs |
|---|---|
| `make check` (default) | `make build vet test lint` |
| `make build` | `go build ./...` |
| `make vet` | `go vet ./...` |
| `make test` | `go test -race ./...` with cgo on |
| `make lint` | `golangci-lint run` (version pinned as `GOLANGCI_LINT_VERSION`) |
| `make fmt` | `golangci-lint fmt` (gofmt and goimports) |
| `make generate` | ocb from `builder-config.yaml`, then `components.go`, `go.mod` and `go.sum` |
| `make dist [VERSION=x.y.z]` | five stripped release binaries in `dist/`, then the size gate |
| `make clean` | removes `dist/` and `build/` |

Two checks stay shell scripts in `scripts/`, called by `make dist` and tested on their own in CI:
`check-binary-size.sh` (the size gate; CI feeds it files just over and at the limit) and `check-version.sh` (the
release version is SemVer; cases in `check-version_test.sh`; GoReleaser replaces it in M3).

## How to work

- Nothing is approved product direction until a spec merges, here in `specs/` or as an org-level spec. Research
  notes, roadmaps and unmerged drafts (including the Forge manifest Ember plans to read) are input, not decisions.
- This repo is public: docs, specs, PR bodies and code comments state a rule inline instead of linking or naming a
  document from a private repo.
- Run `make check` before every push (details in the loop contract): `golangci-lint run`, `go vet ./...`,
  `go test -race ./...`, `go build ./...`. The org Bun CI does not apply here.
- A collector component is added or bumped in `builder-config.yaml`, then `make generate`; never with
  `go get` alone. All component versions come from one upstream release.

## Boundaries

- Never push to `main`, force push or merge. Nazar's code-owner approval is the merge gate.
- No tags or publishing in agent PRs; releases are manual. Agents never dispatch the `Go` workflow's manual release
  build.
